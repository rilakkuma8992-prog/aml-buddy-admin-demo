# AML Buddy Admin Demo

這個資料夾是給 GitHub Pages 上傳的「後台 Demo 版」。

建議 repository 名稱：

```text
aml-buddy-admin-demo
```

部署後網址會像：

```text
https://你的帳號.github.io/aml-buddy-admin-demo/
```

`index.html` 會自動轉到 `admin.html`。

## 後台連到前台

後台左側「開啟前台」已設定為：

```text
https://你的帳號.github.io/aml-buddy-frontend/
```

因此前台 repository 請使用建議名稱 `aml-buddy-frontend`。如果你改用其他 repo 名稱，需要在 `admin.html` 裡修改：

```js
const FRONTEND_REPO_NAME = "aml-buddy-frontend";
```

## Supabase 後端設定

GitHub Pages 是靜態網站；要讓手機、電腦與不同瀏覽器看到同一份已發布題庫，需要外接 Supabase。這個 demo 採用 Supabase Auth + Postgres：

1. 到 Supabase 建立新 Project。
2. 在 SQL Editor 執行下方 SQL 建表、啟用 RLS 與權限。
3. 到 Authentication 建立至少一組 email/password 使用者。
4. 到 Project Settings > API 複製 Project URL 與 anon public key。
5. 在 `admin.html` 與前台 `index.html` 填入 `window.AML_BUDDY_SUPABASE.url` / `anonKey`。
6. 上傳兩個 GitHub Pages repo。
7. 第一次使用時打開後台、登入，點「重設示範資料」可把內建 50 題初始化到 Supabase。
8. 用手機瀏覽器與電腦瀏覽器分別打開前台，確認看到的題庫內容一致。

```sql
create table if not exists public.aml_buddy_faqs (
  id text primary key,
  status text not null default 'draft',
  biz text,
  aspect text,
  category text,
  owner text,
  version text,
  updated_on date,
  effective date,
  next_review date,
  payload jsonb not null default '{}'::jsonb,
  deleted_at timestamptz,
  updated_by uuid references auth.users(id),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists aml_buddy_faqs_status_idx
  on public.aml_buddy_faqs(status);

create index if not exists aml_buddy_faqs_deleted_at_idx
  on public.aml_buddy_faqs(deleted_at);

alter table public.aml_buddy_faqs enable row level security;

drop policy if exists "public read published faqs" on public.aml_buddy_faqs;
drop policy if exists "authenticated read all faqs" on public.aml_buddy_faqs;
drop policy if exists "authenticated insert faqs" on public.aml_buddy_faqs;
drop policy if exists "authenticated update faqs" on public.aml_buddy_faqs;

create policy "public read published faqs"
on public.aml_buddy_faqs
for select
to anon
using (status = 'published' and deleted_at is null);

create policy "authenticated read all faqs"
on public.aml_buddy_faqs
for select
to authenticated
using (true);

create policy "authenticated insert faqs"
on public.aml_buddy_faqs
for insert
to authenticated
with check ((select auth.uid()) is not null);

create policy "authenticated update faqs"
on public.aml_buddy_faqs
for update
to authenticated
using ((select auth.uid()) is not null)
with check ((select auth.uid()) is not null);

grant select on public.aml_buddy_faqs to anon;
grant select, insert, update on public.aml_buddy_faqs to authenticated;

create table if not exists public.aml_buddy_audit_logs (
  id bigint generated by default as identity primary key,
  time text not null,
  user_name text,
  action text,
  target text,
  created_at timestamptz not null default now()
);

alter table public.aml_buddy_audit_logs enable row level security;

drop policy if exists "authenticated read audit logs" on public.aml_buddy_audit_logs;
drop policy if exists "authenticated insert audit logs" on public.aml_buddy_audit_logs;

create policy "authenticated read audit logs"
on public.aml_buddy_audit_logs
for select
to authenticated
using (true);

create policy "authenticated insert audit logs"
on public.aml_buddy_audit_logs
for insert
to authenticated
with check ((select auth.uid()) is not null);

grant select, insert on public.aml_buddy_audit_logs to authenticated;
```

## 刪除策略

題目刪除採「軟刪除」：程式會把 FAQ 標記為 `status = "deleted"` 並寫入 `deleted_at`，不直接從資料表移除。前台只讀 `status = "published"` 且 `deleted_at is null` 的資料，因此已發布題目刪除後不會再顯示；版本與稽核紀錄仍可保留。

## 注意

localStorage 仍保留作為本機草稿／離線暫存；正式發布資料的唯一真相來源是 Supabase。這個 demo 的 Editor／Reviewer 角色仍由頁面上的「展示角色」切換控制，Supabase Auth 先提供登入門檻；正式系統若要防止前端被繞過，應把角色寫入後端權限或 SSO。
